# Retrospective

## 배운 점

### 1. 대시보드는 숫자보다 해석이 중요하다

자산 비중과 수익률을 많이 보여주는 것보다, 사용자가 어떤 흐름으로 포트폴리오를 만들었는지 설명하는 것이 더 중요했습니다.

### 2. 금융 서비스는 문구가 곧 정책이다

같은 분석 결과도 표현 방식에 따라 투자 추천처럼 보일 수 있습니다. 그래서 기능 구현만큼 문장 가드레일이 중요했습니다.

### 3. 해커톤 MVP는 안정성이 중요하다

실시간 API보다 정적 웹앱과 샘플 CSV를 선택한 것은 화려함보다 재현 가능성을 우선한 결정이었습니다.

## 잘한 점

| 항목 | 이유 |
| --- | --- |
| 문제를 행동 리스크로 재정의 | 프로젝트 차별점이 명확해짐 |
| 분석 규칙 문서 작성 | 코드와 결과 해석의 기준 확보 |
| CSV 샘플 제공 | 누구나 즉시 체험 가능 |
| 비추천 원칙 명시 | 서비스 오해 가능성 감소 |

## 아쉬운 점과 개선 방향

| 아쉬운 점 | 개선 방향 |
| --- | --- |
| 실시간 시세 미연동 | 선택형 API 연동 검토 |
| 테스트 자동화 부족 | 분석 함수 단위 테스트 추가 |
| 다양한 사용자 CSV 검증 부족 | 오류 케이스별 샘플 추가 |
| 접근성 점검 제한 | 키보드 이동, 대비, 모바일 가독성 점검 |

## 한 문장 회고

FOMO Guard는 "무엇을 살지"가 아니라 "왜 지금 사고 싶어졌는지"를 묻게 만드는 프로젝트였습니다.
